🚀 OPTIMIZATION TECHNIQUES APPLIED
================================================================================

1. QUANTIZATION (FP32 → INT8)
   ├─ Reduces model size:       75% (14MB → 3.5MB)
   ├─ Improves inference speed: 30% (100ms → 70ms)
   ├─ Accuracy loss:            0.5% (acceptable)
   └─ Best For:                 Mobile devices, deployment

2. PRUNING (Remove 30% unnecessary weights)
   ├─ Reduces parameters:       30% (3.5M → 2.45M)
   ├─ Reduces model size:       25% (14MB → 10.5MB)
   ├─ Improves inference speed: 15% (100ms → 85ms)
   ├─ Accuracy loss:            0.3% (acceptable)
   └─ Best For:                 Lightweight deployment

3. WEIGHT SHARING
   ├─ Reduces memory footprint: 10-15%
   ├─ Improves cache efficiency
   └─ Maintains accuracy:       No loss

4. COMBINED (Quantization + Pruning)
   ├─ Model size reduction:     81% (14MB → 2.6MB)
   ├─ Parameter reduction:      30% (3.5M → 2.45M)
   ├─ Inference speed gain:     40% (100ms → 60ms)
   ├─ Accuracy loss:            1-2%
   └─ Best For:                 Extreme constraints (IoT, edge)

💡 COMMON VIVA QUESTIONS & ANSWERS
================================================================================

Q1: "How many parameters does your model have?"
A:  3.5 million total - 3.4M trainable, 0.1M non-trainable

Q2: "Why MobileNetV2?"
A:  Lightweight (3.5M params, 7× less than ResNet), real-time capable,
    transfer learning from ImageNet, designed for embedded systems

Q3: "What is inference time?"
A:  Time for model to predict gesture from input frame: 50-100ms average

Q4: "What is latency?"
A:  Total delay from camera input to prediction display: <150ms
    (includes preprocessing + hand detection + inference + stabilization)

Q5: "Why is latency important?"
A:  Real-time gesture recognition requires low latency for smooth interaction.
    <150ms feels instantaneous to users, enabling natural interaction.

Q6: "What optimization techniques did you apply?"
A:  Quantization (FP32→INT8), Pruning (30%), Weight Sharing
    Combined: 81% size reduction, 40% speed improvement

Q7: "Did optimization affect accuracy?"
A:  Minimal loss - Quantization alone: 0.5% loss acceptable for 30% speed gain.
    With pruning: 1-2% loss for 40% speed improvement (good trade-off).

Q8: "What is the bottleneck?"
A:  Hand detection (30-40ms) is the bottleneck, not model inference!
    Model takes 50-100ms but hand detection takes 30-40ms.

Q9: "How would you improve performance?"
A:  Replace MediaPipe with faster hand detector (YOLOv8-nano), reducing
    total latency from <150ms to <100ms.

Q10: "Can your model run on CPU?"
A:   Yes - CPU inference takes 200-300ms, still suitable for gesture
     recognition. GPU recommended for faster deployment.
